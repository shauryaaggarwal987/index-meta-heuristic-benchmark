# Meta-Heuristic Optimization of Advanced Index Structures

This repository contains the reproducibility package for the paper:

**Meta-Heuristic Optimization of Performance Trade-Offs in Advanced Index Structures**

The study benchmarks three attribute-specific index structures and their meta-heuristically tuned variants:

- **Fixed Queries Array (FQA)** for numeric exact-match/proximity-style lookup over CGPA values.
- **Burst Trie** for string-key lookup over names.
- **Hash-Bucketed String Index (HBSI)** for exact-match lookup over registration-number strings.

The optimization methods evaluated are:

- Artificial Bee Colony (ABC)
- Particle Swarm Optimization (PSO)
- Grey Wolf Optimizer (GWO)

The paper reports preliminary controlled C++ benchmarking results over 10k, 20k, and 30k records, using two independent trials per configuration.

## Dataset generation

The benchmark dataset is derived from Kaggle's **National Names** dataset.

Expected source file:

```text
NationalNames.csv
```

Expected source columns include:

```text
Name, Count
```

The generator creates a three-column benchmark file:

```text
name,reg_no,cgpa
```

where:

- `name` is copied from the `Name` field.
- `reg_no` is generated sequentially as `REG000001`, `REG000002`, ...
- `cgpa` is a synthetic numeric attribute generated by log-scaling the `Count` field into `[0, 10]`.

Generate the 100k benchmark dataset with:

```bash
python data/generate_students_100k.py \
  --input NationalNames.csv \
  --output data/students_100k.csv \
  --n 100000 \
  --seed 42
```

Important: the generated `cgpa` column is a synthetic benchmarking attribute. It is not real academic CGPA data.

## Build requirements

The experiments were implemented in C++17.

Recommended compiler command:

```bash
g++ -O2 -std=gnu++17 src/benchmarking_code_new.cpp -o bench
```

On Windows/MSYS2 MinGW, the equivalent command is:

```bash
g++ -O2 -std=gnu++17 src/benchmarking_code_new.cpp -o bench.exe
```

## Running baseline benchmarks

The baseline configuration uses:

| Structure | Parameter | Baseline value |
|---|---:|---:|
| FQA | `K` | 16 |
| Burst Trie | `THR` | 32 |
| HBSI | `C` | 64 |

Run baseline benchmarks for 10k, 20k, and 30k records:

```bash
mkdir -p results

./bench --data=data/students_100k.csv --n=10000 --opt=Baseline --csv=results/baseline_10k.csv
./bench --data=data/students_100k.csv --n=20000 --opt=Baseline --csv=results/baseline_20k.csv
./bench --data=data/students_100k.csv --n=30000 --opt=Baseline --csv=results/baseline_30k.csv
```

The benchmark uses a fixed query count of `Q = 2000` and a fixed default seed unless overridden.

## Running tuned optimizer experiments

Compile each optimizer file separately. Example:

```bash
g++ -O2 -std=gnu++17 src/fqa_abc.cpp -o fqa_abc
./fqa_abc --data=data/students_100k.csv --n=30000
```

Repeat similarly for:

```text
fqa_pso.cpp
fqa_gwo.cpp
burst_abc_fixed.cpp
burst_pso_fixed.cpp
burst_gwo_fixed.cpp
hbsi_abc.cpp
hbsi_pso.cpp
hbsi_gwo.cpp
```

Note: the HBSI source files may originally have been named `qfast_abc.cpp`, `qfast_pso.cpp`, and `qfast_gwo.cpp` in earlier project versions. They are renamed here to match the final paper terminology.

## Result interpretation notes

The final paper interprets results under the following scope conditions:

- The structures are evaluated on different attributes and query types, so cross-structure comparisons are attribute-specific rather than universal head-to-head rankings.
- Query values are sampled directly from the indexed dataset, producing a hit-only exact-match workload.
- Memory values are estimated index-memory footprints, not full process-level resident memory.
- The optimizer fitness function is a weighted-sum scalarization, not true Pareto-front multi-objective optimization.
- The reported results use two independent trials per configuration, so they provide preliminary repeatability evidence rather than formal statistical validation.

See `docs/paper_tables_notes.md` for a table-by-table mapping between reported paper results and repository artifacts.
